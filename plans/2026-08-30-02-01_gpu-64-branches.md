# GPU 64 branch 対応計画

## 目的

GPU stroke surface の branch 上限を 64 に拡張し、端末の fragment uniform 制限に応じて安全な動的上限を `supportsBranchCount` に反映する。65 branch 以上は CPU fallback とする。

## 制約

- コミットしない。
- `packages/*/docs` と `work.local/` は編集しない。
- `gpuDab: "off"` の byte-identical、public export、persisted schema は変更しない。

## Phase 1: API 設計・ドキュメント確認

- 既存の engine/input/stroke docs と GPU surface の内部 API を確認する。
- public API・export・schema は変更せず、内部の GPU capacity 判定だけを拡張する。
- ユーザー指定により package docs は読み取り専用とし、本計画に内部設計を記録する。

## Phase 2: 利用イメージレビュー

- 呼び出し側は従来どおり `supportsBranchCount` を利用し、64 以下でも端末制限に収まらない場合は false、65 以上は常に false とする。
- public API の利用方法に変更がないことを確認して Phase 3 に進む。具体的な要求と完了条件はユーザー提示済みのため、今回の依頼を承認済み利用イメージとみなす。

## Phase 3: 実装

- shader uniform の vec4 消費量を算定し、64 branch と WebGL2 最小保証 224 vec4 に収まる表現へ変更する。
- snapshot array、field strip、instance attributes、commit packing の 64 branch 対応を確認し、不足箇所を修正する。
- 64 branch の live/replay、CPU Tier B parity、telemetry sample と、65 branch fallback の browser test を追加する。
- build、lint、test を実行する。

## Phase 4: アーキテクトレビュー

- 要求、内部 API、既存設計、docs との整合性を確認する。
- `review-library-usage` に沿ってセルフレビューし、禁止対象に差分がないことを確認する。
