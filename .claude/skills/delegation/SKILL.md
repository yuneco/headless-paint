# codex 委譲と検収

実装作業を codex に委譲し、結果を検収するための型。
2026-07 の中間層リファクタリング + persistence-hardening（計17タスク超の委譲）で確立した。
**委譲のたびに毎回この型を使う。省略した要素が事故になる。**

## 1. 委譲プロンプトの必須要素（すべて含める）

1. **ブランチ名**と「チェックアウト済み」の明記
2. **必読ファイル**: 計画 md・設計 md の該当節を名指し（「計画を読んで」ではなく節・file:line まで）
3. **対象の列挙**: 変更するファイル・コマンド・イベントを列挙（「〜まわり」と書かない）
4. **変更禁止ファイル**: 互換性の要（データ形式・型定義・API 契約）を明示的に禁止する
5. **合格条件のテスト名**: 「テスト green」だけを完了条件にしない。どのテストが何を検証すれば合格かを指定
6. **停止条件**: 「fixture 不一致」「前提が崩れた」「互換性を壊さないと実装できない」→ 実装を止めて報告、と明記
7. **「コミットしない」**（コミットは検収後に Claude 側で行う）
8. **報告フォーマット**: 何を報告させるか（変更一覧・意図的なテスト更新とその理由・走れなかったテスト名）

## 2. 呼び出しの既知の罠（実測済み）

- `codex exec --full-auto "<プロンプト>" </dev/null` で単独起動。**`</dev/null` 必須**（無いと stdin 待ちでハング）、**`&&` チェーン禁止**
- 難所は `-c model_reasoning_effort=high` を付ける
- **codex sandbox では vitest browser runner が起動できない**（`listen EPERM ::1`）。外部ネットも不可
  - → codex の「テスト通過」報告は**常にノンブラウザ範囲のみ**。browser mode のテスト・E2E は一度も走っていない
  - → golden fixture の焼き直しも codex にはできない。検収側で `vitest run -u` する

## 3. 検収（緑の報告を信じない）

委譲結果を受け取ったら、コミット前に必ず:

1. **フルユニットを自分の環境で実行**（browser mode 込み）。codex が「通過」と言った範囲との差分がここに出る
2. **E2E を実行**（保存・復元・UI に触れた変更では必須）
3. **核心テストの現物確認**: 仕様の要（対応表の行・後方互換・ロールバック・排他）が本当にテスト化されているか grep で確認する。「テストが増えた」≠「核心が検証されている」
4. **golden/fixture の差分は1件ずつ判定**: 「意図的変更」か「事故」か。意図的なら理由をコミットメッセージに記録（例: 2026-07 に golden が「manifest への ArrayBuffer ゴミ混入」という潜在バグを検出した。差分は情報である）
5. **節目には実ブラウザで駆動**（playwright-cli で実フローを再現。ユニットで通っても実経路で壊れる例が実際にあった）
6. すべて green になってから Claude がコミット

## 4. 失敗時の差し戻しの型

検収でテストが落ちたら、**「直して」で返さない**:

1. まず自分で根本原因を特定する（1〜2ファイル読む・単体でテストを走らせる程度の調査は検収側の仕事）
2. 失敗を分類して差し戻す:
   - **production バグ** → 該当テストは**変更禁止**と明記する（テストを実装に合わせて曲げさせないため。これが最重要）
   - **正当なテスト期待値更新**（フォーマット変更への追随等）→ 更新可+理由の報告を要求
   - **環境起因**（sandbox 制約等）→ 検収側で処理し、codex には返さない
3. 特定した事実は「確定済みの根本原因」として差し戻しプロンプトに書く（codex に再調査させない）

実例: 旧形式互換の失敗11件を「1,2 は production 修正・テスト変更禁止 / 3-6 は根本原因を調査して修正 / 7-10 はテスト更新可」と分類して1回で解消した。

## 5. 並列委譲

- コンフリクトしないファイル集合なら 2-3 並列可
- **同一の大きなファイルを触るタスクは直列に**（例: persistenceAtoms.ts を触る2タスクを並列にしない）
- 並列にした委譲の検収は、全部揃ってからまとめて1回

## 6. 委譲しないもの

- 設計判断・対応表の作成・レビュー・検収・コミット・ドキュメントの正本更新 → Claude の仕事
- 読み取り専用レビューは `codex review`（用途を分ける）
